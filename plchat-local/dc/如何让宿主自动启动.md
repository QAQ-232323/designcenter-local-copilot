# 让宿主跟着 Designcenter 自动启动

> 本机已配置好：**Designcenter / NX 一开，宿主几秒内自动起来**（不用手点 `start.cmd`）。
> 开：`dc\autostart-on.cmd`　　关：`dc\autostart-off.cmd`　　不需要管理员。

## 现在的行为

| | |
|---|---|
| 机制 | 登录时启动的看护脚本 `dc\host_watchdog.vbs`（wscript，隐藏窗口） |
| 每 3 秒做两件事 | ① `GET /api/ping` 看宿主在不在；② 不在且 `ugraf.exe` 在跑 → 隐藏拉起 `node server.js 8765` |
| 为什么盯 `ugraf.exe` | 这是所有 Designcenter / NX 版本的主程序名（2606 / 2506 / 2406 / 2306 …），**与版本号无关** |
| 随登录启动 | 启动文件夹里的 `designcenter-local-copilot.vbs` 启动器（由 `autostart-on.cmd` 写入） |
| 自愈 | 宿主进程被杀掉后，只要 DC 还开着，几秒内会被重新拉起 |
| 不会做的事 | 不关宿主（DC 关掉后宿主继续在）、不碰 Designcenter |

**实测**（2026-09-20）：无 `ugraf.exe` 时杀掉宿主，等 12 秒没有被拉起（符合预期）；
用一个顶替 `ugraf.exe` 名字的进程模拟 DC 后，宿主在 12 秒内被自动拉起并响应 `/api/ping`。

## ⚠ 杀毒软件的误报（重要，别再踩）

同一个看护脚本**被火绒删除过一次**：

```
2026/09/20 14:22:05  病毒防护 文件实时监控
发现病毒 TrojanDownloader/VBS.Agent.dd，已处理
病毒路径: <仓库>\plchat-local\dc\host_watchdog.vbs
操作结果: 已处理，删除文件
```

这是**误报**：命中的是"枚举进程 + 隐藏启动程序 + 发 HTTP 请求"这个组合模式，
几乎所有 VBS 下载器都长这样，而我们的脚本只是拉一个本地 Node 服务。

* 现在能用，是因为你把火绒关了（或已放行）。
* **如果哪天换了杀软/重开防护把这个文件删掉**，症状很好认：`dc` 目录里少文件、
  DC 起来后宿主不自动起。两种处理：
  1. 在安全软件里把 `host_watchdog.vbs` 加白（并确认你接受这个文件的行为）；
  2. 退回到**无脚本方案**——用 `HKCU\...\Run` 直接启动 `server.js`（`autostart-on.cmd` 的
     上一个版本就是这么做的，仓库历史里有），代价是失去 DC 门控、退化为"登录就常驻"。
* 不要为了绕过检测去混淆脚本——那是和你的杀毒软件对着干，不值得。

## 为什么不用 Windows 计划任务

计划任务本可以拿到同样的效果（登录触发 + 每分钟重复 + `IgnoreNew`，还能自愈），
但**创建计划任务需要管理员权限**，非提升权限下 `schtasks /Create` 直接返回：

```
错误: 拒绝访问。
```

如果你愿意用管理员装一次，这条路更干净（不依赖 .vbs，也不会被误报）：以管理员身份运行
`cmd`，然后手工执行 `schtasks /Create ...` 或让 AI 把计划任务版本的 `autostart-on.cmd` 恢复。

## 开关与排障

* 装：`dc\autostart-on.cmd`（幂等，重复跑不会起两个看护）
* 卸：`dc\autostart-off.cmd`（杀掉看护、删启动器、删环境变量 `DC_COPILOT_WATCHDOG` 与 conf）
* 看护在跑吗：任务管理器里应有一个 `wscript.exe`，命令行含 `host_watchdog.vbs`
* 宿主在跑吗：`curl http://127.0.0.1:8765/api/ping`（**不要**用 `server.log` 的时间戳判断，
  那是某次手动重定向留下的旧文件，不是程序写的）
* 想改行为：`dc\host_watchdog.conf`（`requireDc=0` 就变成"不管 DC 在不在都拉起"，
  `intervalMs` 改轮询间隔，`node=` 指定 node 路径）
